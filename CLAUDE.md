# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Argus is a multi-agent maritime dark-vessel investigation demo: Strands + LangGraph agents on Bedrock AgentCore, four MCP servers over PostGIS, a FastAPI platform, and OpenTelemetry. Architecture is in `@ARCHITECTURE.md`; the documentation set is indexed in `docs/README.md`; setup and demo flow in `README.md`. Both the local compose stack and the AWS CDK deployment are first-class targets and must stay in sync. Use the vocabulary in `CONTEXT.md` (Alert, Sweep, Investigation, VOI Report, Action, review state vs approval) and check `docs/adr/` before reversing an architectural choice; the phased plan is `docs/ROADMAP.md`.

## Commands

- `.env` comments live on their own lines. Docker compose keeps an inline `# comment` after an empty value as the value (`MODEL_ID=   # note` is a model id to compose, and the agents fail with `model identifier is invalid`); `shared/config.py::clean_env_value` defends the agents, the other services do not.
- `cp .env.example .env` before anything else and set `MODEL_PROVIDER` plus its credential. Default is `bedrock`, which needs `AWS_PROFILE` in `~/.aws` (mounted read-only) and Claude model access in `AWS_REGION`; `anthropic`, `openai`, and `gemini` need their API key env var instead.
- `make up` / `make logs` / `make sweep` / `make investigate` — local stack. `make stop` / `make start` pause with volumes intact; `make down` runs `down -v` and **deletes every volume**.
- AWS lifecycle is CDK-only: `make deploy` (also update), `make stop-aws` (`-c paused=true`: ECS to 0, Aurora auto-pause), `make start-aws`, `make destroy` (destroy + `cdk gc`). Never create AWS resources by CLI in scripts; add a CDK resource or custom resource so destroy can revert it.
- Image assets build from the repo root, and CDK fingerprints the whole build context: `context_excludes` in `infra/cdk/stacks/assets.py` excludes everything an image does not copy (per-image `keep` lists in both stacks, `OBS_CONTEXT` for the consoles); without it any edit anywhere rebuilds all fourteen images and bounces every service on each deploy. When a Dockerfile starts copying a new path, add it to that image's keep list or the build fails with a missing file.
- CDK deploy lessons: ECS Service Connect derives the Cloud Map discovery name from the port-mapping name, so every `ServiceConnectService` must set `discovery_name` explicitly (all services share the `http` port name). CloudWatch Transaction Search is on by default (`-c transactionSearch=false` to skip): the switch needs a CloudWatch Logs resource policy letting `xray.amazonaws.com` write `aws/spans` (`TransactionSearchLogsPolicy`, which the destination custom resource depends on) plus the Application Signals and CloudTrail channel permissions on the custom resource role; without the Logs policy the call fails with "XRay does not have permission to call PutLogEvents" and the platform stack rolls back. Custom resources need `ignore_error_codes_matching` on `on_delete` or a failed rollback wedges the stack. A stack in `ROLLBACK_COMPLETE` must be deleted before `make deploy` can recreate it. AgentCore VPC mode supports only some availability zones (by zone id: `agentcoreZoneIds` in `cdk.json`); `scripts/deploy.sh` resolves them to this account's zone names (`agentcoreAzs`) and the agents stack uses only agent subnets in those zones, so agents may run in a single zone. AgentCore pulls runtime images through the agents' VPC: the agents security group needs 443 egress to the S3 prefix list (ECR layers live in S3) as well as to the VPC CIDR, or every invocation logs `Failed to pull image ... i/o timeout`. The prefix list comes from `ec2.PrefixList.from_lookup`, so synth needs credentials and writes `infra/cdk/cdk.context.json` (gitignored, per account). AgentCore creates runtime log groups itself: never declare `AWS::Logs::LogGroup` for `/aws/bedrock-agentcore/runtimes/*` (retention/removal go through the SDK custom resource in `agents_stack.py`). A rollback that hits AgentCore Memory while it is `CREATING` fails; wait for `ACTIVE` and retry the delete. Service Connect names only resolve in tasks started after the target service existed, so app services depend on the collector and the collector scrapes the API through the internal ALB. The X-Ray OTLP endpoint rejects traces unless Transaction Search is on; the ADOT collector uses the classic `awsxray` exporter instead. Anything the replay task must hand to the API (area, ground truth) goes through the `scenario_meta` table, not `/app/shared`, because they are different hosts on ECS.
- CI gates, run them all before declaring work done (`/ci-local` does this): `ruff check .`, `ruff format --check .`, `pytest -q`, `docker compose config -q`. `make synth` is `|| true` in CI so infra regressions land silently; run it locally when touching `infra/`.
- Ruff is not installed globally; use `uvx ruff@0.16.5 <args>` (matches the CI pin).
- `make eval` scores `/alerts` against `/ground-truth` and needs a running, already-swept stack; run `make sweep` and wait ~90 s first (see `scripts/demo.sh`). `/demo-e2e` automates this.
- Evals' extra deps (`httpx`, `boto3`, `pyyaml`) come from `evals/requirements.txt`, which nothing installs automatically; the inspect-ai harness has its own `evals/requirements-inspect.txt` because inspect-ai pins an older botocore through aioboto3 and cannot share a resolver with boto3 1.43.

## Documentation and diagrams

- Figures are HTML pages under `docs/diagrams/src/` sharing `_design.css`, rendered to 2x PNGs by `make diagrams` (headless Chrome) and committed with their source; no Mermaid, no ASCII art in docs. Wrap every number stated in a figure as `<span data-count="key">N</span>`; `check_counts.py` (run by `tests/test_diagrams.py`) derives the keys from the repo and fails on drift. Docs claim only what the code or an artifact backs.
- `ARCHITECTURE.md` follows a fixed shape: the question it answers, the claim, the hero figure, then stages with their code paths in the headings, honest limitations, where to go deeper. Keep section headings carrying code paths.

## Dependencies and style

- Root `pyproject.toml` holds only ruff/pytest config. Real deps live in seven per-image `requirements.txt` files, all `==` pinned. Keep that: pin exactly, and keep the OTel SDK/instrumentation versions consistent across files.
- Containers install with `uv pip install --system`; CI and `scripts/deploy.sh` use plain `pip`. Python 3.12 everywhere.
- Formatter is `ruff format` at line length 88 (adopted after the codebase was written at 180; the format-on-edit hook runs it for you). Lint rules: E, F, I, B, UP. Do not add `# noqa` for rules that are not selected.
- Never assign a `lambda` to a name (E731); write a `def`.

## Testing

- `tests/` are unit tests and must stay runnable with only `pytest`, `pyyaml`, `pydantic` installed and no Docker, DB, or AWS. That is exactly what CI installs. Do not import strands, langgraph, httpx, psycopg, or boto3 from a unit test.
- Stack-dependent tests are welcome but must carry `@pytest.mark.integration` (registered in `pyproject.toml`) and skip cleanly when the stack is down.
- Run pytest from the repo root: tests rely on `pythonpath = ["."]` and relative paths like `data/scenarios/...`.
- `tests/test_schemas.py` does `sys.path.insert(0, "agents")` on purpose: inside containers `agents/shared` is copied to `/app/shared`, so agent code imports `from shared.config import settings`, never `agents.shared`.

## Model providers

- All model construction goes through `agents/shared/models.py` (`strands_model()` / `langchain_model()`). Never instantiate a provider model class in an agent; add new providers there and in `PROVIDERS` / `DEFAULT_MODEL_IDS` in `shared/config.py`.
- `model_spec()` is pure and unit-tested in `tests/test_model_config.py`; provider SDKs are imported lazily, so keep it that way or the dependency-free test rule breaks.
- Claude 5-family and OpenAI reasoning models reject `temperature`; the spec drops it for them. Don't add sampling params back unconditionally.
- Production is Bedrock-only with Amazon Nova models only (ADR-0002): Lite (fast), Nova 2 Lite (standard), Pro (strong). Do not default any tier to a Claude model; the IAM vendor allowlist is `amazon` alone. The other providers are for dev and evals. On AWS a non-Bedrock key comes from Secrets Manager via `MODEL_API_KEY_SECRET_ARN` (CDK context `modelApiKeySecretArn`), read once at startup. AgentCore Memory always uses Bedrock regardless of provider.

## Gotchas

- **Prompt files use `str.format()`.** Literal JSON braces in `agents/shared/prompts/*.md` must be doubled (`{{ }}`) or `load_prompt` raises `KeyError`. Placeholders in use: `{scenario_end}`, `{schema}`.
- **The scenario clock is `SCENARIO_END`** in replay mode and the wall clock when `AIS_MODE=live` (`scenario_now()` in the API and the ais MCP server, `settings.scenario_end` in agents; all read `AIS_MODE`). It is injected into every prompt as "now", used by the API for track windows, and set in `.env.example`, `docker-compose.yml`, and `infra/cdk/cdk.json`. Change all three together.
- **`data/sql/*.sql` runs only on a fresh `pgdata` volume.** Schema edits are silently ignored until `make down` (or a manual volume delete). `replay.py::apply_schema()` re-applies idempotently for Aurora.
- **Agents block at import until MCP servers are healthy** (`wait_for_mcp`, 180 s) because Strands binds MCP tools at `Agent` construction. Keep compose `depends_on: service_healthy` edges intact; `agent-watch` also depends on `api`. MCP healthchecks live in `mcp-servers/Dockerfile`, not compose.
- **`agent-investigator`'s `A2A_PUBLIC_URL` has a trailing slash** on purpose (a2a-sdk agent card); watch/tasking do not. Do not "normalise" it.
- `IMAGERY_OFFLINE` is read at import time; `GEO_USE_OSM` and `OPENSANCTIONS_API_KEY` per call. Restart `mcp-imagery` to change it.
- `AIS_MODE=live` needs `AISSTREAM_API_KEY` (raises at start without it); live mode has no injected anomalies, so evals are meaningless there. The watched areas are the scenario's box plus the `data/areas.yaml` regions named by `WATCH_AREAS` in both modes (live subscribes to all of them; replay has data only in the scenario box) (`all`, `scenario`, or a comma list; context `watchAreas` on AWS, passed by `deploy.sh`); `services/ais-replay/areas.py` is pure and unit-tested, the replay task publishes `area.areas` and the UI's "watching" selector filters by bbox client-side. Bigger or more areas mean more positions written and more sweep candidates. On AWS, `deploy.sh` reads `AIS_MODE`, `AISSTREAM_API_KEY` and `OPENSANCTIONS_API_KEY` from the environment or `.env`, passes `-c aisMode` / `-c openSanctions`, stores each key in the platform stack's secret after deploy and restarts the task that reads it; keys never enter CDK context.
- Human-in-the-loop is enforced in the API: agents only create `proposed` tasking rows; approve/reject are separate endpoints. Keep it that way.
- AWS: ECS platform images build for `LINUX_AMD64`, AgentCore runtimes for `LINUX_ARM64` (mandatory). Deploy needs Docker buildx.
- AWS network: agents run in the isolated `agents` subnet group with no NAT route (ADR-0007). If an agent needs a new AWS service, add an interface endpoint in `network_stack.py`; never move agents to the private subnets. `infra/cdk/stacks/lifecycle.py` holds the pause flag and the Bedrock-only model guard; synth fails on non-bedrock providers or non-first-party Bedrock models by design.
- `db_url()` is duplicated verbatim in `mcp-servers/common/db.py`, `services/api/main.py`, and `services/ais-replay/replay.py` so each image stays self-contained. Change all three together. Same for `callerauth.py` in `mcp-servers/common/` and `services/api/` (a test asserts they are identical).
- Prompts (ADR-0012): the deploy publishes each `agents/shared/prompts/*.md` to Bedrock Prompt Management (`stacks/prompts.py`; a text change cuts a new immutable version) and the runtimes get `PROMPT_ARN_<ROLE>` / `PROMPT_VERSION_<ROLE>`; `prompts_loader` fetches the managed text once and falls back to the file (manifest `prompt_version` says which). Prompt files use `str.format`, so single-brace placeholders are the only input variables; doubled braces stay literal. Reviews and eval scores are CloudWatch metrics (`Argus/Reviews`, `Argus/Evals`), datasets and batch runs go through `evals/agentcore_dataset.py`.
- Tool plane (ADR-0011): on AWS the four MCP servers are AgentCore Runtime endpoints (`argus_tool_<name>`, private subnets, services SG) behind one AgentCore Gateway (`argus-tools`, IAM inbound, semantic search) with a Policy engine in ENFORCE mode; agents get `TOOL_GATEWAY_URL` and `agents/shared/tools.py` hides gateway vs direct mode. Tool names through the gateway are `<server>___<tool>`. Cedar policies and the registry records come from `mcp-servers/tools.json` (`make tools-inventory`, pinned by a unit test): when a tool is added, regenerate it or the policy blocks the call and the registry lies. Runtimes cannot inject secrets: the servers read `PGPASSWORD_SECRET_ARN` / `OPENSANCTIONS_API_KEY_SECRET_ARN` at start.
- AgentCore Evaluations: a custom evaluator at SESSION level must reference at least one session placeholder in its instructions (`{context}` here; also `available_tools`, `actual_tool_trajectory`, `expected_tool_trajectory`, `assertions`) or CreateEvaluator fails with a validation error and the whole agents stack rolls back. `tests/test_round_two.py` pins it.
- A gateway execution role with a policy engine attached needs exactly the documented set (devguide `policy-permissions`): `bedrock-agentcore:GetPolicyEngine` on `policy-engine/*`, and `AuthorizeAction` + `PartiallyAuthorizeActions` on both `policy-engine/*` and `gateway/*`. CreateGateway checks them one at a time ("Access denied while calling GetPolicyEngine", then "not authorized to perform AuthorizeAction") and each miss costs a full rollback; read the doc page before guessing an IAM action.
- AgentCore resource policies (`CfnResourcePolicy`) must name the resource's own ARN in every statement (`"Resource": "*"` fails PutResourcePolicy with "exactly one resource ARN that matches"); the gateway-only runtime policy is the documented allow-role plus deny-others pair from the runtime-oauth page.
- Agent Registry validates record descriptors against the published schemas strictly: MCP `server.json` 2025-12-11 caps `description` at 100 characters (`short()` in `stacks/tool_policy.py`), the A2A card is 0.3. Validate new descriptors locally with `jsonschema` against the official schema before deploying; `tests/test_round_two.py` pins the MCP limits.
- Gateway runtime targets (`http.agentcoreRuntime`, the agents gateway) take no `credentialProviderConfigurations`: the gateway signs with its own role, and setting GATEWAY_IAM_ROLE fails CreateGatewayTarget with "IamCredentialProvider is not supported for this target type". MCP-server targets (the tools gateway) do need it.
- Agent Registry records are created DRAFT; only APPROVED records are discoverable, and CloudFormation has no property for the step, so `stacks/registry.py` submits each record through an `AwsCustomResource` (`SubmitRegistryRecordForApproval`, auto-approved by APPROVE_ALL). The discoverable listing returns names and status only: read the card with `BatchGetDiscoverableRegistryRecord` (`card_url` in `agents/shared/discovery.py`); the batch read is authorised per record, so callers also need `agent-registry:GetDiscoverableRegistryRecord` / `GetRegistryRecord`. The agent cards in the registry advertise the agents-gateway target URLs, not runtime URLs.
- Interface endpoints declared with `ec2.InterfaceVpcEndpointService(name, 443)` (gateway, agent-registry, bedrock-agent) need `private_dns_enabled=True` explicitly; the `InterfaceVpcEndpointAwsService` enum turns it on by default but the custom service class does not. With it off, `*.gateway.bedrock-agentcore.<region>.amazonaws.com` resolved to public addresses, the isolated agents hung binding tools at start-up, and every invocation returned `424 Failed Dependency` with runtime logs that stop after "model provider=bedrock".
- Agents plane (ADR-0013): agents resolve each other from the AWS Agent Registry (`agents/shared/discovery.py`, worker `registry_agent_url`; `ARGUS_REGISTRY_ID` or SSM `/argus/registry-id`) before falling back to `A2A_*_URL`; A2A calls go through the second gateway `argus-agents` (runtime targets, IAM inbound, `<gateway>/<target>/invocations`). The OpenSanctions key is an AgentCore Identity API-key credential provider backed by the platform secret as JSON `{"api_key": ...}` (deploy.sh stores that shape; `common/identity.py` keeps the runtime's workload access token per request). The Tasking harness (`argus_tasking`) and the orchestrator configuration bundle are pilots: `TASKING_HARNESS_ARN` (context `taskingViaHarness=true`) switches the tasking node to `InvokeHarness`; the report node prefers `report_system_prompt` from a request's bundle. Keying a CFN map by a token (the bundle components) needs `CfnJson`, and inside a `CfnJson` value the keys are CloudFormation's PascalCase names (`Configuration`, not `configuration`), because CfnJson bypasses the L1 property mapping.
- AgentCore Evaluations (`argus_agents`) reads the agents' unified telemetry from their runtime log groups (service names `argus_<name>.DEFAULT`), so the runtimes must not override `OTEL_EXPORTER_OTLP_*`; `ARGUS_OTLP_ENDPOINT` is the extra span exporter to the platform collector. CloudWatch Transaction Search is on by default (`-c transactionSearch=false` to skip). No X-Ray/EMF/log fan-out, no CloudWatch dashboard or alarms: Grafana (one board, `argus`) and Grafana alerting to SNS are the operator view.
- `AWS::AgentRegistry::*` and the AgentCore Gateway/Policy/Evaluations resources are CloudFormation types; the registry has no CDK module, so `stacks/registry.py` uses raw `CfnResource`. The gateway endpoint (`*.gateway.bedrock-agentcore.<region>.amazonaws.com`) and the registry are reached from the agents' subnets through interface endpoints (`network_stack.py`).
- Caller identity: agents prove who they are with an STS-signed token (`agents/shared/caller_auth.py`); servers verify it in `callerauth.py` when `TOOL_AUTH=aws-iam` and allow by IAM role name (`TOOL_ALLOWED_ROLES`, fail-closed). Agent-only API routes are listed in `_AGENT_ROUTES` in `services/api/main.py`; add new agent endpoints there or they stay open.
- Evals: detector tests in `tests/integration` run in CI against PostGIS and must stay model-free; model-in-the-loop evals live in `evals/` with floors in `thresholds.yaml`. A prompt or model change is not done until `evals/node_evals.py --gate` passes against a stack. Pure scoring helpers belong in `evals/scoring.py` (unit-tested, no httpx).
- The Orchestrator is a code graph (`agents/orchestrator/app.py` + pure `agents/shared/graph.py`); do not reintroduce an LLM that chooses the sequence. Models come from tiers (`for_tier(role)` in `shared/models.py`); the only LLM in the orchestrator is the report node. Report output must pass `shared/policy.py`.
- `mcp-servers/serve.py` disables FastMCP's DNS-rebinding host check (it is enabled at construction because the default host is localhost); without that every request through the internal ALB gets `421 Misdirected Request`. Keep it off; `callerauth.py` is the access control.
- Product wording: no demo or synthetic disclaimers in agent output or tool sources. Report caveats are set by `data_caveats()` from `AIS_MODE` and `SANCTIONS_SOURCE`; tool sources are `local-registry` / `local-list` / `opensanctions` / `aisstream`.
- Observability on AWS is both CloudWatch/X-Ray and a self-hosted Grafana+Tempo+Loki+Prometheus Fargate task (`grafanaStack`, default on; configs in `observability/aws/`, images in `services/observability/`). Grafana keeps its state in a `grafana` database on Aurora (SQLite on EFS took twenty minutes to migrate and failed the load-balancer health check); Prometheus uses the task's ephemeral disk; only Tempo and Loki use EFS. Consoles behind the public ALB use the stack-owned `ConsolesSg`, and the internal ALB carries the stack-owned `InternalConsolesSg` for the console listener ports: both load balancers otherwise carry only the immutable imported services group, so listener or health-check rules added to it are dropped silently (symptoms: load-balancer health checks fail, collector exports time out). Grafana resets its admin password from the secret on every start (`Dockerfile.grafana`), because Grafana applies the env password only to an empty database. Containers in that task talk over localhost, so their internal ports must not collide (Loki gRPC is moved to 9096; Tempo keeps 9095); the collector reaches them through the internal ALB (tempo 4319, loki 3100, prometheus 9090) so it has no start-order dependency on them; a dependency there created a CloudFormation cycle with the replay task that creates their databases. The collector is the upstream contrib image (`--config=env:OTEL_CONFIG`). Every ECS service has the deployment circuit breaker with rollback: a crash-looping task must roll back on its own, because CloudFormation otherwise waits hours for it to stabilise.
- CloudWatch panel legends in the builder are written as `{{Dimension}}` and `cw()` rewrites them to Grafana's dynamic label `${PROP('Dim.Dimension')}`; the CloudWatch plugin on Grafana 12 shows the brace form literally.
- The Grafana board is generated: edit `observability/grafana/build_dashboards.py` (the persona builders are the panel library; `SECTIONS` is the layout), run `make dashboards`, commit both outputs (`observability/grafana/dashboards/argus.json`, `observability/aws/dashboards/argus.json` with the AgentCore/CloudWatch section). Alert rules live in `observability/aws/alerting.yaml` and route to the SNS topic. The officer's review is a CloudWatch metric (`Argus/Reviews`, `services/api/review_metrics.py`); eval scores go to `Argus/Evals` with `--push`.
- `worker.py::reap_orphans` fails jobs still `running` past `timeout_s + JOB_REAP_GRACE_S`: a worker restart (every compose recreate, every ECS rollout) otherwise leaves rows `running` forever, which the KPI strip and the evals' idle wait counted as load.
- Worker concurrency is `WORKER_CONCURRENCY` (2 locally, 4 on AWS); handlers stay idempotent because two workers may race on a redelivery. Live mode ingests AIS static data (`aisstatic.py`) into `vessels` and `registry` for real vessels; scenario rows (`is_synthetic`) are never overwritten. A Bedrock Guardrail is created in `agents_stack.py` and reaches both frameworks through `model_spec()`; keep PII masking off.
- Grafana provisioning is fatal: a bad `alerting.yaml` (for example an SNS contact point without `topic_arn`) stops the Grafana process, so the observability task fails its load-balancer health check and the deployment rolls back. Run the AWS Grafana image locally (`services/observability/Dockerfile.grafana`) before deploying provisioning changes.
- AgentCore runtime session ids are `rt-<investigation id>-<role>` (`runtime_session_id` in `agents/shared/graph.py` and `services/api/runtime_session.py`, kept identical). The runtime stamps its session id on every span, so the collector's `transform/session` processor folds it back to the bare investigation id; that is what makes one session per investigation in every trace store. Parallel branches must never share a runtime session (AgentCore answers a second concurrent call with 409).
- `CfnGuardrailVersion` is a snapshot: editing the guardrail only updates the DRAFT and the runtimes keep the old version. The version resource's description carries a hash of the policy so a policy change replaces it (new version number flows into `BEDROCK_GUARDRAIL_VERSION`). Replaced versions are retained (`RemovalPolicy.RETAIN`): deleting the old version while the runtimes still referenced it failed every model call for the minutes until they rolled. Check `aws bedrock get-guardrail --guardrail-version N` after a deploy.
- Guardrail calibration (agents_stack.py): no denied topic for personal surveillance (the topic classifier blocks about 20% of live Investigator prompts with one, TopicPolicy applies on input, and a blocked prompt fails both branches; check `InvocationsIntervened` by `GuardrailPolicyType` before adding a topic). PROMPT_ATTACK input LOW and MISCONDUCT input LOW / output NONE on purpose. Bedrock applies the prompt-attack filter to the whole prompt and ours are machine-built (tool results are not read by it), and reports must describe suspected smuggling or sanctions evasion; at HIGH the guardrail blocks ~3% of ordinary calls (a whole Investigator branch or a report retry each time). `guardrail_blocked()` still recognises the canned block text: the report node retries once with a plainer correction list and records `guardrail_blocked`; the Investigator reports `guardrail blocked the request` instead of `no JSON`. Watch `InvocationsIntervened` by policy type before tightening anything.
- AgentCore Memory long-term extraction lags by minutes and works on user/assistant pairs (`memory_messages`), so `VesselMemory.recall` also reads the raw assistant events of the last three sessions (`ListSessions`/`ListEvents`); a repeat investigation sees the previous run immediately.
- The Watch sweep is a deterministic pre-pass plus judgement: `list_candidates` (agents/watch/app.py) runs the detectors through a short-lived MCP client and `shared/sweep.py` builds candidates with fixed mmsi, kind, window and evidence; `raise_alert`/`dismiss_candidate` take a candidate id. Never let the model supply mmsi or windows: Nova Lite copies one vessel's gap window onto another and the eval recall swings between 0.4 and 0.8 run to run. `non_dismissible()` keeps definitional anomalies out of the model's hands too: an MMSI from two places and a rendezvous outside any declared anchorage can only be raised (Nova Lite dismisses the scenario's at-sea transfer as "normal operations" about once in two runs). Candidates are ranked and capped per sweep (`SWEEP_MAX_CANDIDATES`, default 25); the rest are deferred.
- Alert kinds are `ais_gap`, `mmsi_spoof`, `loitering`, `zone_incursion`, `rendezvous` (`ALERT_KINDS`); models echo detector names (`mmsi_conflict`), so `normalise_kind` in the Watch tool and the API's `AlertIn` validator map aliases. `raise_alert` requires `started_at`/`ended_at`: the eval scorer matches alerts to ground truth by time overlap, and an alert without a window scores zero.
- Evidence sources are cited as `server.tool`. LangChain's MCP adapter gives the Investigator bare tool names, so `findings_payload` prefixes them from the tool→server map built in `InvestigatorGraph.graph()`; the eval's `TOOL_PREFIXES` and the report policy both expect the dotted form.
- Strands agents (Watch, Tasking) run with `SlidingWindowConversationManager(should_truncate_results=True)`: a sweep reads many tracks and Nova rejected the request with `Input Tokens Exceeded` before it could raise anything. `get_vessel_track` downsamples to 120 points by default for the same reason.
- `evals/node_evals.py` must parse agent answers with the agents' own `json_object` (first complete object; prose after it ignored) and coerce Tasking answers with `tasking_payload`, or schema-shaped answers score as invalid while the orchestrator accepts them.
- Any free text an MCP server returns from an external source goes through `common/safety.untrusted()`.
- Jobs: never run agent work in a FastAPI background task. Create a `jobs` row through `enqueue()` / `open_investigation()` in `services/api/main.py`; `services/api/worker.py` runs it. Handlers must be idempotent (at-least-once delivery). Transient vs permanent failure is decided by `is_transient` in `jobqueue.py`.
- `audit_events` is append-only by trigger. Every API state change must call `audit()`; never update or delete rows there.
- Findings carry `review_state` (draft/accepted/rejected); actions carry approval status. Do not conflate them (see `CONTEXT.md`).
- Schema changes go in a new numbered file under `data/sql/` written idempotently (`IF NOT EXISTS`); `replay.py` applies every file except `000_*` on Aurora and locally on every start. The shared Docker volume is mounted at `/app/shared`, never `/app/data`: a volume over `/app/data` shadowed the image's SQL directory and hid new migrations.
- `positions` is range-partitioned by day and has **no primary key** on purpose (spoofed MMSIs and duplicate AIS reports share `(mmsi, ts)`). Use `positions_ensure_partitions` before bulk inserts. Never add `ON CONFLICT` to position inserts.
- Personal data (`registry.beneficial_owner`, person entity names) exists only encrypted (`pgp_sym_encrypt` with the data key from `datakey.py`, three identical copies). Read it with `pgp_sym_decrypt` in the registry MCP tool only; the API and UI stay pseudonymous.
- psycopg picks the narrowest integer type for parameters, so calls to SQL functions with BIGINT/REAL/JSONB arguments need explicit casts (`%s::bigint`), or overload resolution fails.
- On Apple Silicon set `POSTGIS_IMAGE=imresamu/postgis:17-3.5` in `.env`; the official `postgis/postgis` image is amd64-only.
- UI map rules (learned the hard way): the map runs on an inline plain style and the CARTO vector basemap is merged in underneath our layers after the first idle frame. Never call `setStyle` to switch basemaps (a diffed update strips our layers without firing `style.load`, and a full reload holds every frame until sprite and tiles arrive). Draw vessels as circle and line layers, not symbol icons. CARTO raster tiles need an API key; only the vector style is free. In replay mode the database already holds the whole scenario, so positions and staleness follow the SSE stream clock and fall back to the database only when the stream is idle. The replay loops (`REPLAY_LOOP`) so the demo never goes quiet.
- UI keyboard shortcuts: review actions need Shift so stray typing can never accept or reject; shortcuts are scoped to the Alerts tab.
- Officer identity (ADR-0018): `OFFICER_AUTH=oidc` on AWS makes every non-public, non-agent API route require the ALB's `x-amzn-oidc-data` token or an IAM caller (`services/api/officerauth.py`, outermost middleware; `needs_iam` feeds `CallerAuthMiddleware`). Locally `OFFICER_AUTH=header`. Route handlers take `officer_id: str = Depends(current_officer)`, never a header. Scripts against AWS assume `argus-operator` (`make eval-aws`); root or IAM-user credentials are refused by design.
- Public ALB is HTTPS only with Cognito on both listeners (UI, Grafana); `/api/*` with a bearer header bypasses the sign-in at the ALB and is checked by the API. Without `uiCertificateArn` the certificates come from the `CertificateIssuer` custom resource (`infra/cdk/lambdas/selfsigned`, bundled with Docker at synth: `python:3.14-slim`, so synth needs Docker). The internal ALB's API listener is HTTPS too; agents trust it via SSM `/argus/internal-ca` (`agents/shared/tls.py`), the collector scrapes it with `insecure_skip_verify`.
- Database password rotates monthly. `db_url()`/`_password()`/`refresh_password()` are duplicated verbatim in `services/api/dbconn.py`, `mcp-servers/common/db.py`, `services/ais-replay/replay.py` (a test pins them identical). API and worker use `RotatingPool` from `dbconn.py`; never create a bare `ConnectionPool` there.
- Jobs: one queue per kind (`argus-sweeps`, `argus-jobs`), one worker service per kind (`WORKER_QUEUE_KIND`), timeout ladder `node×depth < timeout_s < visibility < timeout_s + grace` pinned by `tests/test_jobs.py`; the worker heartbeats visibility and `reclaim`s a stuck `running` row on redelivery (ADR-0016).
- The ALB's `x-amzn-oidc-data` token keeps `=` padding in its segments and is signed over them as sent: `verify_id_token` hands the raw token to PyJWT and only `split_jwt` normalises padding for parsing. Re-encoding the segments makes every real sign-in fail with `Signature verification failed` (the UI then shows "starting, waiting for positions" and 401s on every route); `tests/test_officerauth.py` signs a padded ES256 token to pin it.
- `sns.Topic(enforce_ssl=True)` installs a topic policy that replaces SNS's default one: CloudWatch Alarms publish as the `cloudwatch.amazonaws.com` service principal and need an explicit allow on the topic (`AllowCloudWatchAlarms` in `platform_stack.py`, pinned by `tests/test_alarms.py`) or every alarm action fails with "CloudWatch Alarms is not authorized to perform: SNS:Publish" while the alarm itself still flips. Check `describe-alarm-history --history-item-type Action` after a deploy.
- On a fresh deploy the sweep schedule can fire before the agents stack exists; that first sweep job fails with `ParameterNotFound` (the worker resolves the Watch runtime through SSM) and is not retried. The next scheduled sweep succeeds; nothing to fix unless it repeats.
- Alarms live in `infra/cdk/stacks/alarms.py`; every alarm name must appear in the RUNBOOK table (`tests/test_alarms.py`). Grafana rules in `observability/aws/alerting.yaml` include the eval gate and API scrape loss; run the AWS Grafana image locally before changing that file.
- cdk-nag runs in `app.py` on every synth (`-c nag=false` to skip); a new finding fails synth until fixed or suppressed with evidence in `infra/cdk/stacks/nag.py`. `cdk-nag` must stay on 2.x (3.0.x fails with `aspect.visit is not a function` under this aws-cdk-lib).
- Tier escalation also fires on provider availability errors (`model_unavailable` in `shared/models.py`): Investigator retries once on the next tier, the report node rebuilds its agent on the next tier; the API publishes `Argus/Investigations` (Completed, DegradedBranches, Escalations) on `/complete`.
- Pilots are off by default: `bundleOverride` (report prompt from a request's configuration bundle), `taskingViaHarness`. The manifest attests the prompt that ran (`bundle:<version>` label).
- Personal-data decrypts go through `datakey.decrypting(lambda k: q(..., (k, ...)))` (three identical `datakey.py` copies, pinned by `tests/test_rekey.py`): a wrong-key error re-reads the secret once. Re-keying is `make rekey-aws` (`services/api/rekey.py` + `data/sql/009`), never a Secrets Manager rotation schedule.
- `scripts/deploy.sh` reads `OFFICER_EMAIL` / `OFFICER_MFA` from the environment or `.env` and passes them as `officerEmail` / `officerMfa`; deploy as the `argus-deployer` role through an AWS profile with `mfa_serial`, not root.
